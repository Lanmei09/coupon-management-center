# 专项 A · 优惠券基础能力后台原型

## 打开方式

直接打开同目录下的 `index.html`。原型是无依赖的静态 HTML/CSS/JS 文件，不需要安装或启动服务。

主要入口：

- `#activities`：活动列表
- `#templates`：券模板列表；“新建券模板”从列表工具栏打开
- `#coupon-form`：优惠券配置/批次列表，查看关联模板、活动和配置规模
- `#coupon-create-form`：新增/编辑优惠券配置；按“选择券类型（自定义类型可选择券模板） → 填写基本信息 → 动态高级设置 → 关联活动”的顺序完成配置
- `#coupon-detail`：优惠券配置详情；顾客券实例只作为示例，完整实例进入记录页
- `#dashboard`：优惠券看板
- `#records`：发放与核销记录

页面内的新增、编辑、复制、停用、筛选、详情、异常重试等操作使用 mock 数据演示，刷新页面会恢复初始数据，也可以使用左下角“重置演示数据”。

## 本版范围

- 仅后台管理端；顾客端领券、我的优惠券、充值页和结算页仍保留在参考原型中。
- 导航层级遵循：活动中心 → 优惠券中心（优惠券列表、优惠券管理），优惠券管理只保留券模板；活动管理中心（活动列表）、数据与记录（看板、流水）保持独立。
- 发放规则不作为本期原型层级；活动新建/编辑和活动详情只维护活动本身及其关联优惠券。
- 券模板表单已按“优惠计算方式 + 顾客资格 + 场景标签”拆分。
- “优惠券列表”展示的是基于模板生成的优惠券配置/批次，不展示顾客券实例；新增优惠券页面先选择券类型，只有“自定义类型”在类型区域选择可复用券模板，最后关联活动，保存不会直接生成顾客券。
- 券模板负责复用规则；优惠券配置负责生效范围和后续发放；顾客券实例只有在新客、充值、主动领取、人工或 CDK 执行时才生成，并保留发放时规则快照。
- 活动表单只配置场景、触发事件和时间；优惠券关联从活动详情跳转到优惠券列表完成，避免活动和优惠券各维护一套规则。
- 真实接口、权限鉴权和支付服务未接入；接口结论以 `04-现有接口能力地图.md` 为准。
